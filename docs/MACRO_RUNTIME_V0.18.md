# Macro Runtime v0.18 — Governed Desktop Interaction Adapter\n\n## Status\n\nv0.18 is the first Macro Runtime rung that can perform one real bounded desktop\ninteraction.\n\nIt routes the exact Ghost-Walk click operation through the existing PhiOS\ncapability, permission, effect, binding, ActionLease, execution, and receipt\npipeline.\n\n## Core boundary\n\n~~~\nOBSERVATION != AUTHORITY\nSEMANTIC CLEAR != CLICK AUTHORITY\nPIXEL CLEAR != CLICK AUTHORITY\nACTIONLEASE != GUARANTEED EFFECT\nEXECUTOR ENTRY != CLICK PERFORMED\nPARTIAL INPUT != SUCCESS\nRECEIPT != VALIDATION OF APPLICATION OUTCOME\n~~~\n\n## Adapter-to-capability mapping\n\nGhost-Walk v0.13 records clicks as:\n\n~~~\nadapter_id = desktop.interaction\naction = click\nrequired_capabilities = (ui.interact,)\n~~~\n\nv0.18 preserves that operation identity and maps it explicitly to:\n\n~~~\ndesktop.interaction + click\n-> desktop.interaction.click\n~~~\n\nThe operation hash is not rewritten.\n\nThe existing MacroSpineBridge still validates the exact operation inputs,\nPlanActionBinding, payload hash, permission scope, and ActionLease binding.\n\nUnknown adapter/action pairs remain fail-closed.\n\n## Governed capability\n\ninstall_desktop_click_capability() registers:\n\n~~~\ncapability_id = desktop.interaction.click\nversion = 0.18.0\npermissions = (ui.interact,)\neffects = (display.control, filesystem.change)\nrisk = high\n~~~\n\nThe filesystem effect covers the executor's governed result artifact.\n\nThe action effect is display.control.\n\n## Exact Ghost-Walk payload\n\nDesktopClickRequest accepts the v0.13 click payload only:\n\n- observation SHA-256;\n- preferred strategy;\n- expected process ID;\n- expected window-title SHA-256;\n- complete PixelAnchor;\n- optional SemanticTarget;\n- absolute_pixel_is_evidence_only = true;\n- guard_required = true.\n\nUnknown or missing fields fail closed.\n\nA request cannot disable its guard or promote the original absolute desktop\npixel into an execution target.\n\n## Two target proof paths\n\n### Semantic\n\nFor SEMANTIC requests, the executor calls the merged v0.17\nSemanticReplayRevalidator immediately before injection.\n\nThe target must resolve to one unique safe current UIA element.\n\nA HOLD semantic receipt aborts the desktop action.\n\n### Window-relative pixel\n\nFor WINDOW_RELATIVE_PIXEL requests, the executor:\n\n- resolves the v0.12 PixelAnchor against the current foreground frame;\n- checks the window currently covering that resolved coordinate;\n- detects process/title overlay mismatch;\n- samples current pointer and last-input state;\n- runs the v0.12 InteractionGuard.\n\nA HOLD pixel guard aborts the desktop action.\n\n## Race guard before injection\n\nAfter either target proof returns CLEAR, the executor samples the desktop again.\n\nThe click is refused if:\n\n- foreground process changed;\n- foreground title changed;\n- window geometry changed;\n- display scale changed;\n- foreground state changed;\n- operator last-input token changed;\n- pointer position changed;\n- resolved coordinate moved outside the verified frame;\n- another root window now covers the resolved coordinate.\n\nThis closes the gap between target proof and input injection.\n\nCaptured timestamps are not used as window identity.\n\nTwo WindowFrames are considered the same live frame state by comparing process,\ntitle, geometry, DPI scale, and foreground state.\n\n## ActionLease attempt semantics\n\nOnce the governed Spine has admitted the executor, the single-use ActionLease\nrepresents one bounded execution attempt.\n\nIf the last-millisecond race guard HOLDs inside the executor:\n\n- no click is injected;\n- a HELD DesktopInteractionReceipt is persisted;\n- the Spine records the executor attempt as failed;\n- the ActionLease remains consumed.\n\nThis is deliberate.\n\nAuthority is not silently reusable after the environment changed.\n\n## Windows injector\n\nWindowsMouseInjector uses SendInput for exactly three events:\n\n~~~\n1. absolute virtual-desktop move\n2. left button down\n3. left button up\n~~~\n\nCoordinates are normalized against the full Windows virtual desktop, including\nmulti-monitor layouts.\n\nThe injector performs one left-click only.\n\nIt does not type text, drag, scroll, right-click, or hold the mouse.\n\n## Injected-event isolation\n\nThe merged v0.15 listener preserves Windows injected-event flags.\n\nTherefore the SendInput events produced by v0.18 are observed as injected and\nare HELD by the Ghost-Walk recorder path rather than learned as new human\ndemonstrations.\n\n## Input outcomes\n\nSendInput results are interpreted conservatively:\n\n~~~\n3 / 3 inserted -> SUCCEEDED\n0 / 3 inserted -> FAILED\n1 or 2 / 3 inserted -> OUTCOME_UNKNOWN\n~~~\n\nA partial input sequence may have changed the desktop in an uncertain way.\n\nIt is never relabeled as success or safe failure.\n\nOUTCOME_UNKNOWN propagates through the existing Spine reconciliation path.\n\n## Desktop interaction receipt\n\nReality Ledger adds:\n\n~~~\ndesktop-interaction-receipts.jsonl\n~~~\n\nDesktopInteractionReceipt binds:\n\n- exact request hash;\n- semantic/pixel target mode;\n- fresh target-proof receipt hash;\n- preflight/final/post frame hashes;\n- frame provider ID;\n- operator input probe ID;\n- injector ID;\n- before/final last-input tokens;\n- before/final pointer coordinates;\n- resolved click coordinate;\n- inserted event count;\n- SUCCEEDED / HELD / FAILED / OUTCOME_UNKNOWN;\n- exact reason;\n- effect_performed true / false / unknown;\n- zero authority flags.\n\nA successful receipt is also written as a governed JSON result artifact and\nreturned through the existing Spine ArtifactResult path.\n\n## Full governed path\n\n~~~\nGhost-Walk MacroDefinition\n-> MacroRunner WAITING_OPERATION\n-> GovernedDoDispatcher\n-> desktop.interaction/click mapping\n-> PlanActionBinding\n-> verified single-use ActionLease\n-> MacroSpineBridge\n-> GovernedLeasedExecutionHandoff\n-> PhiOS Spine permission/effect gates\n-> GovernedDesktopClickExecutor\n-> fresh semantic or pixel proof\n-> race guard\n-> Windows SendInput\n-> DesktopInteractionReceipt\n-> ExecutionReceipt\n-> MacroSpineReceipt\n-> DoDispatchReceipt\n-> OperationResolution\n-> MacroRunner resumes\n~~~\n\n## v0.18 acceptance gates\n\n### DESKTOP-001 — semantic bounded click\n\nA fresh unique semantic target performs exactly one 3-event left-click sequence\nand persists a successful receipt.\n\n### DESKTOP-002 — pixel bounded click\n\nA fresh CLEAR InteractionGuard may resolve a current window-relative coordinate\nand perform one bounded click.\n\n### DESKTOP-003 — operator interference\n\nChanged last-input token or pointer position HOLDs before injection.\n\n### DESKTOP-004 — frame drift\n\nForeground process/title/geometry/DPI/foreground drift HOLDs before injection.\n\n### DESKTOP-005 — overlay drift\n\nA different root window covering the final target coordinate HOLDs.\n\n### DESKTOP-006 — semantic ambiguity\n\nA v0.17 ambiguous semantic target HOLDs with no injection.\n\n### DESKTOP-007 — partial injection\n\nA partial SendInput sequence becomes OUTCOME_UNKNOWN.\n\n### DESKTOP-008 — zero injection\n\nZero inserted input events becomes FAILED with effect_performed=false.\n\n### DESKTOP-009 — guard cannot be disabled\n\nGhost-Walk payloads with guard_required=false are rejected.\n\n### DESKTOP-010 — full macro authority path\n\nAn original desktop.interaction/click macro operation can pass through the\ndispatcher, explicit adapter mapping, exact binding, verified ActionLease,\nSpine gates, desktop executor, and back to a COMPLETED MacroRunner.\n\n### DESKTOP-011 — platform boundary\n\nReal Windows frame/input/injector components refuse construction on non-Windows\nsystems.\n\n## Deliberate non-goals\n\nv0.18 does not yet:\n\n- type text;\n- press keyboard shortcuts;\n- drag/drop;\n- scroll;\n- right-click;\n- invoke UIA InvokePattern;\n- retry a failed click automatically;\n- reuse a consumed ActionLease;\n- infer that the application achieved the desired semantic result.\n\n## Next rung\n\nv0.19 should add post-action state verification.\n\nAfter a bounded interaction succeeds, PhiOS should observe a declared expected\nstate transition, such as a target disappearing, a new semantic control\nappearing, a verified window/title/state change, or another explicit\napplication-specific observation.\n\nThe click receipt proves what input PhiOS attempted.\n\nIt does not yet prove the application did what the macro intended.
