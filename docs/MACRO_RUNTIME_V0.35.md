# Macro Runtime v0.35 — Lease-Consuming Ghost-Walk Execution Handoff\n\nMacro Runtime v0.35 is the first Ghost-Walk rung allowed to enter the real\nPhiOS executor path.\n\nIts public execution surface is intentionally one value:\n\n```text\nexecute(action_lease_sha256)\n```\n\nThere is no caller-supplied capability, payload, permission set, effect set,\ntarget, policy, authority epoch, or replay override.\n\n## Core boundary\n\n```text\nLEASE ID\n    ↓\nPhiOS custody recovery\n    ↓\ncurrent binding / policy / enforcement / authority revalidation\n    ↓\natomic single-use lease claim\n    ↓\nexact stored executable payload\n    ↓\nPhiOS Spine\n    ↓\nExecutionReceipt\n```\n\nThe governing invariant is:\n\n```text\nACTION LEASE != EXECUTION\n\nEXECUTION = CURRENT LEASE + EXACT BINDING + CURRENT POLICY\n          + CURRENT AUTHORITY + EFFECT BOUNDARY + PERMISSION GATE\n          + SINGLE-USE CLAIM\n```\n\n## No fake plan provenance\n\nThe existing GovernedLeasedExecutionHandoff is intentionally plan-shaped.\nGhost Walk does not originate from a planner transition, so v0.35 does not\nmanufacture a synthetic PlanState merely to satisfy that older interface.\n\nInstead, Spine accepts a distinct zero-authority GhostWalkExecutionProvenance\ncarrying the exact target inference, AuthorizationDecision, executable binding,\nv0.34 lease custody record, ActionLease, AuthorityEpoch, lease policy, and\nEnforcementProfile. The existing plan-shaped ExecutionProvenance is unchanged.\n\n## Custody and current-state checks\n\nThe ActionLease hash resolves the nested v0.34 GhostWalkActionLeaseRecord.\nMissing, duplicate, malformed, or hash-tampered custody fails closed.\n\nAt execution time PhiOS then rechecks:\n\n- the exact v0.33 binding is still current;\n- the server-owned lease policy digest is unchanged;\n- the EnforcementProfile reconstructs exactly;\n- acknowledged unenforced effects are unchanged;\n- the current AuthorityEpoch digest still matches the lease;\n- the current Spine capability version, permissions, and effects still match;\n- the registered executor effect contract still passes the EffectBoundary.\n\nAny drift holds before executor entry.\n\n## Single-use claim\n\nv0.35 reuses RealityLedger.claim_action_lease(). It does not introduce a\nsecond lock or consumption database. A competing or abandoned claim fails\nclosed as lease_execution_claim_unavailable and is replay-blocked.\n\n## Exact payload execution\n\nAfter the claim succeeds, PhiOS invokes Spine.run() with the capability and\npayload recovered from the immutable executable binding. Afterward the\ncanonical Spine ExecutionReceipt must report the exact capability, payload\ndigest, requested permissions, and Ghost-Walk provenance.\n\n## Consumption semantics\n\nPermission denial before executor entry releases the claim and does not consume\nthe lease. Once the executor is entered, SUCCEEDED, FAILED, and OUTCOME_UNKNOWN\nall consume the lease. FAILED and OUTCOME_UNKNOWN keep effect state unknown,\nbecause uncertainty is not permission to retry an effectful action.\n\n## Reality Ledger\n\nv0.35 adds append-only ghostwalk-lease-execution-receipts.jsonl. The existing\nprimary Spine ExecutionReceipt remains the source of executor-entry and runtime\noutcome facts. Its Ghost-Walk provenance contains the ActionLease hash, so the\nexisting has_consumed_action_lease() logic continues to work.\n\n## Authority boundary\n\nThe v0.35 handoff and outer receipt carry:\n\n```text\naction_authority    = false\nexecution_authority = false\n```\n\nAction authority remains solely in the exact current ActionLease. The handoff\nproves that authority is current, bounded, single-use, and tied to the exact\nstored deed before the executor is entered.\n\n## Next rung\n\nOnce v0.35 is green, PhiVessel can receive the narrow transport:\n\n```text\nobserve(...)\npropose(...)\nexecute(leaseId)\n```\n\nVessie must never mint, expand, renew, replace, rebind, or transfer a lease.\n
