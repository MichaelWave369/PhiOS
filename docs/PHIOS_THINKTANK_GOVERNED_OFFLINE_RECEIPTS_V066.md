# PhiOS v0.66: opt-in genuine ThinkTank offline-build receipts

**Scope:** producer bridge only, no installed app or distributed package.

PR #368 verified real compiled ThinkTank bytes from a pinned,
network-disabled Docker build. PR #369 checked PhiOS's package-planning and
installer contracts using **synthetic** receipts and temporary HTML/JS.
Neither produced real PhiOS v0.32 build/offline receipts for ThinkTank.

This rung supplies a **separate opt-in execution adapter** that delegates
receipt production to the actual PhiOS \`NpmOfflineBuildService.execute()\`.
It never manufactures receipt fields and always feeds service outputs to the
existing v0.65 exact-file package gate.

## Trust boundaries and operation

The v0.66 script accepts four files provided by the operator:
- v0.64 real pinned \`thinktank-preinstall-handoff.json\` (review-only)
- a real v0.32 derived \`NpmOfflineBuildPlan\` produced with
  \`derive_npm_offline_build_plan()\` from a reviewed v0.28 source/build plan
  and a real v0.32 cache receipt
- the matching PhiOS source acquisition receipt, from the v0.27 service
- the matching PhiOS npm cache receipt from the v0.32 cache preparation service

These last three inputs must come from the existing PhiOS source acquisition,
lockfile/dependency broker, npm cache and build planning APIs. They are NOT
replaced by the earlier hosted Chrome or Docker JSON receipts.

The gate insists on original source commit
\`655d96f7ff892c9989f75cf874e74689f7694127\`, source repository,
exact candidate manifest, root-relative Vite assets and **only two approved
build steps**: \`npm ci --offline --cache /phios/npm-cache\` and
\`npm run build\`. Build permissions are limited to \`build.process.execute\`
and \`build.workspace.write\`, with no dependency network permission.

### 1. Preflight, no process execution

\`\`\`bash
python scripts/thinktank_governed_offline_producer.py \
  --handoff /PRIVATE/thinktank-preinstall-handoff.json \
  --offline-plan /PRIVATE/real-phi-offline-plan.json \
  --acquisition-receipt /PRIVATE/real-source-acquisition.json \
  --npm-cache-receipt /PRIVATE/real-npm-cache-receipt.json
\`\`\`

Review the emitted \`offline_plan_sha256\`, source pin, reviewed host/cache
provenance and legal restrictions. This does not authorize a build.

### 2. Only after separate exact operator approval for disposable private build

\`\`\`bash
python scripts/thinktank_governed_offline_producer.py \
  --handoff /PRIVATE/thinktank-preinstall-handoff.json \
  --offline-plan /PRIVATE/real-phi-offline-plan.json \
  --acquisition-receipt /PRIVATE/real-source-acquisition.json \
  --npm-cache-receipt /PRIVATE/real-npm-cache-receipt.json \
  --execute-disposable \
  --approve-offline-plan-sha REVIEWED_EXACT_64_HEX_PLAN_DIGEST \
  --approve-source-sha 655d96f7ff892c9989f75cf874e74689f7694127 \
  --private-execution-root /PRIVATE/disposable-phios-builds \
  --private-receipt-root /PRIVATE/disposable-phios-receipts \
  --output /PRIVATE/thinktank-v066-review.json
\`\`\`

Execution must use an isolated ephemeral environment with an independently
reviewed source intake and staged npm dependency cache; the CLI does not
obtain this authorization from PR merge or CI pass.

The actual PhiOS service performs a network-denied Bubblewrap build, emits
the canonical build-execution, sandbox and npm-offline receipts, and checks
their persistence. The v0.66 adapter independently checks required v0.32
network controls and compares the compiled file bytes and Vite asset closure
with the v0.64 inventory through v0.65's package gate.

If the compiled assets differ, the command fails. This does **not**
prove reproducibility across independent platforms. It also does not erase
receipts already generated by the service, so the operator should use a
fresh disposable private workspace.

If everything matches, the JSON has
\`REAL_PHIOS_OFFLINE_BUILD_RECEIPTS_MATCH_HANDOFF_REVIEW_ONLY\`, *not*
\`APP_INSTALLED\` or \`PRODUCTION_DONE\`.

## Testing, no actual ThinkTank execution in PR CI

\`\`\`bash
pytest -q tests/test_thinktank_governed_offline_producer.py
\`\`\`

The new tests use a fake receipt-producing service to verify preflight and
exact approval refusal, fixed source pin, no-network plan shape, no install
or release authority, and rejection of failed isolation or mismatched bytes.
The underlying authentic v0.32 service's separate regression tests exercise
its production service with a fake sandbox. Neither test is evidence that
actual ThinkTank v0.32 receipts were produced.

**No automatic PR CI action invokes \`--execute-disposable\`.** No public
compiled assets, node cache, package archive, secrets, or model provider
are exported by this change.

## What remains before an actual installed ThinkTank

1. Explicit operator review of real source/acquisition and approved dependency
   staging hosts, pinned lockfile hashes, licenses, redistribution and native
   dependencies. Preserve v0.69 holds, even if the private build succeeds.
2. Run the genuine v0.32 offline service on the pinned upstream commit in an
   isolated private environment; record real receipt IDs, control evidence,
   compiled artifact digests and whether the v0.65 gate matched.
3. Obtain separate reviewed **package-plan approval** and a guest-only
   installation decision, without publishing third-party bundles.
4. Exercise only the existing \`AppInstallService\`, static adapter, desktop
   grant, guest Chrome launch, no-ISO reboot/persistence and v0.40
   update/rollback in a disposable QEMU VM.
5. Do not claim physical Windows/macOS/Quest/Android readiness or a native
   PhiOS production install from tests, mocks or a successful hosted build.

**Ledger Above Ego: source pin -> genuine producer receipt -> actual bytes ->
explicit approval -> isolated guest install -> observed UI -> rollback.**
