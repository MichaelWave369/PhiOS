# Macro Runtime v0.20 — Ghost-Walk Transition Inference\n\n## Status\n\nv0.20 compares immutable demonstrated before/after UI state snapshots and\nproposes editable, zero-authority candidate postconditions for the merged\nv0.19 post-action verifier.\n\nIt performs deterministic difference detection.\n\nIt does not claim to infer human intent or causation.\n\n## Core boundary\n\n~~~\nOBSERVED DIFFERENCE != HUMAN INTENT\nOBSERVED AFTER != CAUSED BY ACTION\nINFERRED CANDIDATE != ACCEPTED POSTCONDITION\nEDITABLE NOTE != IMMUTABLE EVIDENCE\nNO OBSERVABLE CHANGE != NO EFFECT\nSCOPE CHANGE != SAFE INFERENCE\n~~~\n\n## State snapshot\n\nGhostWalkUiStateSnapshot binds one demonstrated action to one BEFORE or AFTER\nstate:\n\n- session ID;\n- action observation SHA-256;\n- phase: BEFORE or AFTER;\n- process ID;\n- window-title SHA-256;\n- WindowFrame SHA-256;\n- sorted unique SemanticTargets;\n- observation timestamp;\n- zero authority flags.\n\nSemantic targets must be deterministically sorted by target SHA-256 and unique.\n\nThe before and after snapshots must:\n\n- belong to the same Ghost-Walk session;\n- bind the same demonstrated action;\n- use BEFORE then AFTER phases;\n- be temporally ordered.\n\n## Deterministic inference rules\n\nv0.20 intentionally uses a small rule set.\n\n### Window title changed\n\nIf process identity is stable and the title hash changes:\n\n~~~\ncandidate -> WINDOW_TITLE_CHANGED\n~~~\n\n### Semantic target appeared\n\nIf one SemanticTarget exists after the action but not before:\n\n~~~\ncandidate -> SEMANTIC_PRESENT(target)\n~~~\n\n### Semantic target disappeared\n\nIf one SemanticTarget exists before the action but not after:\n\n~~~\ncandidate -> SEMANTIC_ABSENT(target)\n~~~\n\n### Stable target\n\nA target present in both snapshots produces no candidate.\n\n### No observed differences\n\n~~~\nNO_OBSERVABLE_CHANGE\n~~~\n\nThis does not mean no application effect occurred. It only means the supplied\nobservation surface did not expose one of the supported differences.\n\n### Process change\n\nIf the before and after process IDs differ:\n\n~~~\nSCOPE_CHANGED\n~~~\n\nNo v0.19 candidate is fabricated because the current v0.19 expectation model\nis intentionally scoped to a stable expected process.\n\n## Candidate contract\n\nEach TransitionCandidate carries:\n\n- deterministic candidate ID;\n- inference basis;\n- exact v0.19 PostActionExpectation;\n- before snapshot SHA-256;\n- after snapshot SHA-256;\n- human_intent_confirmed = false;\n- causation_proven = false;\n- zero authority flags.\n\nCandidate IDs are sorted deterministically in the inference receipt.\n\n## Inference receipt\n\nTransitionInferenceReceipt binds:\n\n- session ID;\n- demonstrated action observation hash;\n- before snapshot hash;\n- after snapshot hash;\n- CANDIDATES / NO_OBSERVABLE_CHANGE / SCOPE_CHANGED;\n- complete candidate set;\n- inference timestamp;\n- human_intent_confirmed = false;\n- causation_proven = false;\n- zero authority flags.\n\n## Persistent evidence\n\nReality Ledger adds:\n\n~~~\nghostwalk-ui-state-snapshots.jsonl\ntransition-inference-receipts.jsonl\n~~~\n\nThese streams are immutable evidence.\n\n## Editable operator log\n\nv0.20 reuses the merged v0.12 OperatorLog instead of creating a second mutable\nannotation system.\n\nAn inference receipt can publish a human-readable note containing:\n\n- inference status;\n- inference receipt hash;\n- candidate IDs;\n- candidate basis;\n- v0.19 expectation kind;\n- semantic name hints when available;\n- explicit intent/causation firewalls.\n\nThe operator can revise or retract that note through the existing versioned\nOperatorLog.\n\nEditing the note:\n\n~~~\nDOES NOT mutate the inference receipt\nDOES NOT accept a candidate as human intent\nDOES NOT create authority\n~~~\n\nThis preserves Jeffrey's requested editable workflow log without mixing human\nannotation with immutable machine evidence.\n\n## Acceptance gates\n\n### TRANSITION-001 — deterministic differences\n\nA demonstration containing a title change, one appeared semantic target, one\ndisappeared target, and one stable target yields exactly three deterministic\ncandidate postconditions. The stable target yields no noise.\n\n### TRANSITION-002 — no observable difference\n\nIdentical supported state produces NO_OBSERVABLE_CHANGE with no candidates.\n\n### TRANSITION-003 — process scope change\n\nA process transition produces SCOPE_CHANGED rather than a fabricated v0.19\npostcondition.\n\n### TRANSITION-004 — same demonstrated action\n\nBefore/after snapshots referring to different action hashes are rejected.\n\n### TRANSITION-005 — temporal ordering\n\nAFTER must occur strictly after BEFORE.\n\n### TRANSITION-006 — editable note firewall\n\nEditing the operator note creates a new note revision while the immutable\ninference receipt remains unchanged and still reports human_intent_confirmed=false.\n\n### TRANSITION-007 — unique semantic inventory\n\nDuplicate semantic targets in one state snapshot are rejected.\n\n## Deliberate non-goals\n\nv0.20 does not yet:\n\n- automatically enumerate an entire live Windows UIA window before/after;\n- decide which candidate the human intended;\n- automatically attach a candidate to an executable macro;\n- assign confidence scores;\n- infer causality;\n- infer arbitrary text/value changes;\n- use OCR or screenshots;\n- create execution authority.\n\n## Next rung\n\nv0.21 should add the real Windows before/after semantic-state observer.\n\nThat observer should inventory a privacy-bounded set of stable UIA identities\ninside the expected process/window, cap collection size, avoid control values\nand secrets, and feed exact snapshots into this v0.20 inference engine.\n\nAfter that, a separate operator-adoption rung can turn a reviewed candidate into\nan exact v0.19 post_action_expectation inside the macro operation payload.
