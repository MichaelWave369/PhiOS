# Macro Runtime v0.17 — Semantic Selector Scope + Replay Revalidation\n\n## Status\n\nv0.17 adds the semantic replay proof layer between recorded Ghost-Walk UIA\ntargets and any future desktop interaction adapter.\n\nIt resolves a recorded v0.16 SemanticTarget against the current verified\nprocess/window and returns CLEAR or HOLD evidence.\n\nIt does not inject desktop input and does not grant authority.\n\n## Core boundary\n\n~~~\nRECORDED SELECTOR != CURRENT TARGET\nUIA MATCH != UNIQUE MATCH\nUNIQUE MATCH != SAFE MATCH\nSEMANTIC CLEAR != CLICK AUTHORITY\nFRESH COORDINATE != EXECUTION PERMISSION\nUNKNOWN UI STATE != SAFE\n~~~\n\n## Replay input\n\nSemanticReplayRevalidator receives:\n\n- recorded SemanticTarget;\n- expected process ID;\n- expected window-title SHA-256;\n- fresh WindowFrame;\n- fresh observation timestamp.\n\nThe current frame must match the expected process and window and must be\nforeground before the UIA backend is queried.\n\n## Selector contract\n\nv0.17 currently accepts only selectors produced by:\n\n~~~\nprovider = windows.uia.v0.16\n~~~\n\nwith the exact selector schema:\n\n~~~\n{\n  "automation_id": "...",\n  "control_type": 50000 | null\n}\n~~~\n\nUnsupported providers or malformed selector fields HOLD before replay lookup.\n\n## Real Windows replay backend\n\nComtypesWindowsUiaReplayBackend extends the optional v0.16 comtypes backend.\n\nIt searches the Windows UI Automation desktop tree using AutomationId and, when\nrecorded, ControlType.\n\nCandidate results are scoped to:\n\n- the current expected process;\n- the current window geometry when element bounds are available.\n\nThe scan is safety-bounded.\n\nAs soon as two in-scope candidates are found, uniqueness is disproven and the\nbackend may stop collecting more.\n\n## Candidate multiplicity\n\nCandidate multiplicity is preserved even when two UIA elements produce identical\nsnapshot hashes.\n\nTwo indistinguishable elements are still two matches.\n\nTherefore:\n\n~~~\n0 candidates -> HOLD TARGET_MISSING\n1 candidate  -> continue safety validation\n2+ candidates -> HOLD TARGET_AMBIGUOUS\n~~~\n\nSnapshot hash deduplication must never turn ambiguity into uniqueness.\n\n## Candidate safety validation\n\nA unique UIA candidate must also satisfy:\n\n- candidate process equals the expected process;\n- AutomationId exactly matches;\n- recorded ControlType matches when present;\n- enabled state is known and true;\n- offscreen state is known and false;\n- bounding rectangle is known;\n- bounding rectangle remains fully inside the current verified window.\n\nUnknown enabled/offscreen/bounds state HOLDs.\n\nThis follows the existing PhiOS rule:\n\n~~~\nUNKNOWN != SAFE\n~~~\n\n## Fresh semantic coordinate\n\nWhen one candidate passes all checks, v0.17 derives a fresh coordinate from the\ncenter of the candidate's current UIA bounding rectangle.\n\nThat coordinate is not authority.\n\nIt is evidence for a future desktop interaction adapter.\n\nThe intended later chain is:\n\n~~~\nrecorded SemanticTarget\n-> fresh UIA replay lookup\n-> unique safe candidate\n-> fresh current control center\n-> SemanticRevalidationReceipt(CLEAR)\n-> normal PhiOS authority checks\n-> future desktop interaction adapter\n~~~\n\nNo stale recorded desktop pixel is required when semantic replay succeeds.\n\n## Persistent evidence\n\nReality Ledger adds:\n\n~~~\nsemantic-revalidation-receipts.jsonl\n~~~\n\nEach SemanticRevalidationReceipt binds:\n\n- recorded target hash;\n- fresh WindowFrame hash;\n- expected process ID;\n- expected window-title hash;\n- replay backend ID;\n- CLEAR / HOLD;\n- exact reason;\n- candidate count;\n- candidate snapshot hashes, preserving multiplicity;\n- selected snapshot hash when CLEAR;\n- fresh resolved center coordinate when CLEAR;\n- observation timestamp;\n- zero authority flags.\n\nCandidate UiaElementSnapshots are also persisted through the existing v0.16\nsnapshot stream.\n\n## HOLD reasons\n\nv0.17 distinguishes:\n\n~~~\nPROVIDER_UNSUPPORTED\nSELECTOR_INVALID\nPROCESS_MISMATCH\nWINDOW_MISMATCH\nNOT_FOREGROUND\nBACKEND_ERROR\nTARGET_MISSING\nTARGET_AMBIGUOUS\nCANDIDATE_PROCESS_MISMATCH\nAUTOMATION_ID_MISMATCH\nCONTROL_TYPE_MISMATCH\nENABLED_UNKNOWN\nDISABLED\nOFFSCREEN_UNKNOWN\nOFFSCREEN\nBOUNDS_UNKNOWN\nBOUNDS_OUTSIDE_WINDOW\n~~~\n\nThis makes a stopped macro explainable instead of merely reporting that the\ndesktop click failed.\n\n## v0.17 acceptance gates\n\n### REVALIDATE-001 — unique safe target\n\nExactly one valid visible enabled candidate returns CLEAR and a fresh center\ncoordinate.\n\n### REVALIDATE-002 — missing target\n\nZero matches HOLD as TARGET_MISSING.\n\n### REVALIDATE-003 — ambiguity\n\nTwo or more matches HOLD as TARGET_AMBIGUOUS, including two candidates with\nidentical snapshot hashes.\n\n### REVALIDATE-004 — process scope\n\nA current WindowFrame from the wrong process HOLDs before backend lookup.\n\n### REVALIDATE-005 — window scope\n\nA mismatched current window title HOLDs before backend lookup.\n\n### REVALIDATE-006 — foreground scope\n\nA non-foreground window HOLDs before backend lookup.\n\n### REVALIDATE-007 — candidate safety\n\nCandidate process, AutomationId, ControlType, enabled/offscreen state, and bounds\nare revalidated fail-closed.\n\n### REVALIDATE-008 — backend failure\n\nA replay backend exception produces HOLD BACKEND_ERROR.\n\n### REVALIDATE-009 — provider scope\n\nSemantic targets from unsupported providers HOLD before backend lookup.\n\n### REVALIDATE-010 — selector schema\n\nMalformed or extended selector schemas HOLD before backend lookup.\n\n### REVALIDATE-011 — immutable zero-authority receipt\n\nSemantic replay decisions persist separately and carry no execution authority.\n\n### REVALIDATE-012 — platform boundary\n\nThe real comtypes replay backend refuses construction on non-Windows systems.\n\n## Full Ghost-Walk path after v0.17\n\n~~~\nhuman click\n-> v0.15 Windows listener\n-> v0.14 window capture\n-> v0.16 UIA semantic observation\n-> v0.13 Ghost-Walk demonstration\n-> draft macro\n\nlater replay:\n\nrecorded semantic selector\n-> fresh WindowFrame\n-> v0.17 unique-selector revalidation\n-> CLEAR / HOLD\n-> authority boundary\n-> future desktop interaction adapter\n~~~\n\n## Deliberate non-goals\n\nv0.17 does not yet:\n\n- invoke UIA controls;\n- click the resolved center coordinate;\n- obtain ui.interact authority;\n- create ActionLeases;\n- use InvokePattern;\n- set control values;\n- fall back automatically from failed semantic replay to pixel execution;\n- handle keyboard/text replay;\n- capture secrets.\n\n## Next rung\n\nv0.18 should add the Governed Desktop Interaction Adapter.\n\nThat adapter should accept only already-authorized macro operations, require either\na CLEAR semantic revalidation receipt or a CLEAR pixel InteractionGuard receipt,\nrevalidate the evidence binding immediately before action, and then perform one\nbounded desktop interaction with a post-action receipt.\n
