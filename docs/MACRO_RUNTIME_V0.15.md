# Macro Runtime v0.15 — Windows Ghost-Walk Listener\n\n## Status\n\nv0.15 adds the real Windows low-level mouse observation listener around merged\nv0.14 capture.\n\nThe listener observes genuine and injected left-button events, preserves their\nWindows provenance, and feeds the exact v0.14 adapter contract.\n\nIt never injects desktop input.\n\n## Core boundary\n\n~~~\nLISTENING != EXECUTION\nHOOK OWNERSHIP != UI AUTHORITY\nLOW-LEVEL INPUT EVENT != HUMAN DEMONSTRATION\nINJECTED FLAG != OPTIONAL METADATA\nCALLBACK SPEED != BUSINESS LOGIC\nLISTENER SEQUENCE != IN-MEMORY COUNTER\n~~~\n\n## Windows low-level hook\n\nWindowsGhostWalkListener installs:\n\n~~~\nSetWindowsHookExW(WH_MOUSE_LL)\n~~~\n\nand observes:\n\n~~~\nWM_LBUTTONDOWN\n~~~\n\nThe callback reads MSLLHOOKSTRUCT fields:\n\n- desktop x/y;\n- Windows hook flags;\n- hook timestamp in milliseconds;\n- dwExtraInfo.\n\nOnly observation APIs are used.\n\nThe listener contains no SendInput, mouse_event, synthetic click, keyboard\ninjection, or desktop-control path.\n\n## Injected-event provenance\n\nWindows exposes:\n\n~~~\nLLMHF_INJECTED\nLLMHF_LOWER_IL_INJECTED\n~~~\n\nRawMouseHookEvent preserves both flags.\n\nEither flag makes raw_event.injected true.\n\nLOWER_IL_INJECTED also remains separately visible in the listener receipt.\n\nv0.14 then HELDs the normalized PointerClickEvent before window lookup.\n\nThis prevents future PhiOS-generated clicks from being learned as new human\ndemonstrations.\n\n## Minimal hook callback\n\nA critical v0.15 rule is:\n\n~~~\nWH_MOUSE_LL callback != capture pipeline\n~~~\n\nLow-level Windows hooks are time-sensitive.\n\nThe callback therefore does only:\n\n~~~\ncopy MSLLHOOKSTRUCT\n→ build RawMouseHookEvent\n→ timestamp observation\n→ put into bounded queue\n→ CallNextHookEx immediately\n~~~\n\nIt does not perform:\n\n- window lookup;\n- semantic lookup;\n- JSONL writes;\n- GhostWalkRecorder reconstruction;\n- draft compilation.\n\nThose operations run on a separate observation worker.\n\nThis directly protects against long-run hook timeout / silent removal behavior.\n\n## Bounded observation queue\n\nThe callback uses a bounded queue:\n\n~~~\nMAX_PENDING_HOOK_EVENTS = 1024\n~~~\n\nIf the consumer cannot keep up and the queue saturates, the listener stops with\nan explicit error rather than accumulating unbounded memory or silently dropping\nhuman input.\n\n## Listener bridge\n\nGhostWalkListenerBridge converts one raw Windows left-button observation into:\n\n~~~\nRawMouseHookEvent\n→ persisted listener sequence\n→ deterministic PointerClickEvent\n→ v0.14 GhostWalkCaptureAdapter\n→ GhostWalkCaptureReceipt\n→ GhostWalkListenerReceipt\n~~~\n\nThe PointerClickEvent identity is derived from:\n\n- listener ID;\n- persisted listener sequence;\n- Ghost-Walk session ID;\n- raw event hash;\n- observation timestamp.\n\n## Persisted anti-drift sequence\n\nReality Ledger adds:\n\n~~~\nghostwalk-listener-receipts.jsonl\n~~~\n\nEach listener receipt binds:\n\n- listener ID;\n- contiguous listener sequence;\n- Ghost-Walk session ID;\n- raw hook event SHA-256;\n- normalized PointerClickEvent SHA-256;\n- v0.14 capture receipt SHA-256;\n- capture status;\n- injected flags;\n- observed timestamp;\n- previous listener receipt SHA-256;\n- zero authority flags.\n\nBefore every new listener event, the bridge reloads all prior receipts for that\nlistener, verifies each receipt hash, verifies contiguous sequence, and verifies\nthe previous-receipt hash chain.\n\nThe next event sequence is therefore derived from persisted evidence, not an\nin-memory callback counter.\n\n## Restart behavior\n\nA new GhostWalkListenerBridge with the same listener ID continues from the next\nvalidated persisted sequence.\n\nExample:\n\n~~~\nprocess A records listener sequence 0\nprocess exits\nprocess B reconstructs ledger\nnext event becomes sequence 1\n~~~\n\nChanging an old receipt while leaving its sequence plausible fails hash\nvalidation before another event can be recorded.\n\n## Stop behavior\n\nstop() posts WM_QUIT to the listener thread's own message queue.\n\nThis is process-control signaling, not desktop input injection.\n\nThe Windows hook is then uninstalled.\n\nThe observation worker drains queued events before shutdown when possible.\n\nIf the queue is saturated or the observation worker cannot terminate within the\nbounded shutdown interval, the listener fails explicitly.\n\n## v0.15 acceptance gates\n\n### LISTENER-001 — human click path\n\nA genuine Windows-style left-button observation becomes a v0.14 RECORDED\ncapture and one v0.13 GhostWalkObservation.\n\n### LISTENER-002 — injected provenance\n\nBoth Windows injected flags survive normalization and result in v0.14 HELD\ncapture with no demonstration observation.\n\n### LISTENER-003 — restart sequence\n\nA reconstructed bridge continues the persisted listener sequence rather than\nresetting to zero.\n\n### LISTENER-004 — deterministic event identity\n\nIdentical listener/session/sequence/raw/timestamp inputs produce identical\nPointerClickEvent and listener receipt hashes.\n\n### LISTENER-005 — sequence tamper\n\nNon-contiguous persisted listener sequence state fails closed.\n\n### LISTENER-006 — persisted zero-authority receipt\n\nListener receipts persist outside the execution ledger and carry no authority.\n\n### LISTENER-007 — platform boundary\n\nWindowsGhostWalkListener refuses construction on non-Windows systems.\n\n### LISTENER-008 — zero-authority raw event\n\nRawMouseHookEvent carries no operational, action, or execution authority.\n\n### LISTENER-009 — receipt tamper\n\nEditing a prior listener receipt fails hash validation before the next observed\nevent can continue.\n\n## Full Ghost-Walk observation path\n\nPhiOS now has:\n\n~~~\nWindows WH_MOUSE_LL\n→ minimal callback\n→ bounded observation queue\n→ observation worker\n→ RawMouseHookEvent\n→ persisted listener provenance\n→ PointerClickEvent\n→ v0.14 window / semantic capture\n→ v0.13 hash-chained GhostWalkObservation\n→ zero-authority macro draft\n~~~\n\nThat is the first complete path from a real Windows mouse observation to a\nstructured PhiOS macro demonstration.\n\n## Deliberate non-goals\n\nv0.15 does not yet:\n\n- capture keyboard events;\n- record typed text;\n- capture wheel/drag gestures;\n- discover UI Automation selectors itself;\n- expose a PhiShell Record button;\n- automatically start/stop Ghost-Walk sessions;\n- inject mouse or keyboard input;\n- execute desktop.interaction operations.\n\n## Next rung\n\nv0.16 should add the real Windows semantic UI provider using Microsoft UI\nAutomation.\n\nThat provider should inspect the element at the observed point and emit stable\nSemanticTarget candidates when possible, while preserving the guarded pixel\nanchor when UIA is unavailable or ambiguous.\n
