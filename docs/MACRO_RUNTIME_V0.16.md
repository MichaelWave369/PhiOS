# Macro Runtime v0.16 — Windows UI Automation Semantic Provider\n\n## Status\n\nv0.16 adds the first real Windows semantic target provider for Ghost-Walk.\n\nIt enriches the merged v0.14/v0.15 click-observation path with Microsoft UI\nAutomation identity metadata while preserving the v0.12 guarded pixel anchor as\nfallback.\n\n## Core boundary\n\n~~~\nUIA ELEMENT != EXECUTION AUTHORITY\nSEMANTIC TARGET != CURRENT TARGET PROOF\nAUTOMATION ID != GLOBAL UNIQUENESS\nWEAK LABEL != STABLE SELECTOR\nSEMANTIC FAILURE != LOST DEMONSTRATION\nCONTROL IDENTITY != CONTROL VALUE\n~~~\n\n## Optional Windows dependency\n\nThe base PhiOS install remains OS-independent.\n\nWindows UI Automation support is exposed through the optional extra:\n\n~~~\npip install phios[uia]\n~~~\n\nThe extra uses comtypes 1.4.x to access UIAutomationCore.dll.\n\nLinux CI and non-Windows installs do not require comtypes.\n\n## Privacy-bounded UIA snapshot\n\nUiaElementSnapshot records identity metadata only:\n\n- process ID;\n- AutomationId;\n- short name hint;\n- numeric UIA control type;\n- class name;\n- framework ID;\n- enabled state;\n- offscreen state;\n- password-control flag;\n- bounding rectangle;\n- zero authority flags.\n\nIt does not read or persist:\n\n- ValuePattern values;\n- text-entry contents;\n- password contents;\n- HelpText;\n- document text;\n- clipboard data.\n\nA password control may still produce a strong AutomationId selector, but the\nSemanticTarget name hint is redacted.\n\n## Point lookup backend\n\nComtypesWindowsUiaBackend uses Microsoft UI Automation:\n\n~~~\nUIAutomationCore.dll\n→ CUIAutomation\n→ IUIAutomation.ElementFromPoint\n~~~\n\nand reads current identity properties from the element at the observed pointer\nlocation.\n\nThe backend is observation-only.\n\nIt performs no InvokePattern, SetValue, selection changes, focus changes, or\ninput injection.\n\n## Conservative semantic promotion\n\nWindowsUiaSemanticProvider does not treat every UIA element as a stable target.\n\nPromotion currently requires:\n\n~~~\nUIA element exists\nAND UIA process == captured WindowFrame process\nAND element bounds contain the observed click when bounds are available\nAND element is not reported offscreen\nAND AutomationId is non-empty\n~~~\n\nOnly then is a SemanticTarget emitted.\n\nThe selector is a canonical JSON object containing:\n\n~~~\nautomation_id\ncontrol_type\n~~~\n\nThe Ghost-Walk operation already carries process and window-title identity from\nv0.13, so the semantic selector remains scoped by the surrounding interaction\ncontract rather than pretending AutomationId is globally unique.\n\n## Weak or contradictory UIA evidence\n\nUIA evidence is preserved but not promoted when:\n\n- no element exists at the point;\n- UIA reports a different process than the captured window;\n- AutomationId is missing;\n- the element bounds do not contain the click;\n- the element is reported offscreen.\n\nThose cases return no SemanticTarget.\n\nv0.14 therefore keeps the human demonstration using:\n\n~~~\nWINDOW_RELATIVE_PIXEL\n~~~\n\n## UIA failure behavior\n\nIf the UI Automation backend raises an error:\n\n~~~\nUiaLookupReceipt(decision=ERROR)\n→ provider re-raises\n→ v0.14 catches semantic lookup failure\n→ human click is still recorded\n→ guarded pixel anchor becomes preferred\n~~~\n\nA broken accessibility provider does not erase the demonstration.\n\n## Persistent semantic evidence\n\nReality Ledger adds:\n\n~~~\nuia-element-snapshots.jsonl\nuia-lookup-receipts.jsonl\n~~~\n\nThe snapshot records what UIA exposed.\n\nThe lookup receipt records what PhiOS concluded from it.\n\nThose are deliberately separate claims.\n\nUiaLookupReceipt binds:\n\n- PointerClickEvent SHA-256;\n- WindowFrame SHA-256;\n- semantic provider ID;\n- backend ID;\n- FOUND / NO_ELEMENT / AMBIGUOUS / FRAME_MISMATCH / ERROR;\n- reason;\n- optional snapshot hash;\n- optional SemanticTarget hash;\n- zero authority flags.\n\n## Integration with Ghost-Walk\n\nThe observation path is now:\n\n~~~\nWindows WH_MOUSE_LL\n→ v0.15 listener\n→ v0.14 WindowFrame capture\n→ v0.16 UIA ElementFromPoint\n→ strong SemanticTarget when justified\n          or\n  guarded PixelAnchor fallback\n→ v0.13 GhostWalkObservation\n→ zero-authority MacroDefinition draft\n~~~\n\n## v0.16 acceptance gates\n\n### UIA-001 — strong AutomationId\n\nA matching, visible element with a non-empty AutomationId becomes a semantic\ntarget and persists both snapshot and lookup receipt.\n\n### UIA-002 — missing AutomationId\n\nA UIA element without AutomationId is AMBIGUOUS and falls back to pixels.\n\n### UIA-003 — process mismatch\n\nUIA identity from a different process is not promoted.\n\n### UIA-004 — password name redaction\n\nA password element may retain stable identity while its semantic name hint is\nredacted.\n\n### UIA-005 — no element\n\nNo UIA element produces NO_ELEMENT without fabricating a snapshot.\n\n### UIA-006 — backend failure\n\nA backend exception leaves an ERROR receipt and is re-raised to v0.14.\n\n### UIA-007 — ambiguous integration\n\nv0.14 records the click with WINDOW_RELATIVE_PIXEL when UIA is ambiguous.\n\n### UIA-008 — error integration\n\nv0.14 records the click with pixel fallback when UIA fails.\n\n### UIA-009 — privacy boundary\n\nThe persisted snapshot schema contains identity metadata but no control value or\ntext-content field.\n\n### UIA-010 — platform boundary\n\nThe comtypes backend refuses construction on non-Windows systems.\n\n### UIA-011 — strong integration\n\nA strong UIA target flows through v0.14 and becomes SEMANTIC in the Ghost-Walk\nobservation.\n\n### UIA-012 — point/bounds contradiction\n\nAn element whose bounds do not contain the observed click is AMBIGUOUS.\n\n### UIA-013 — offscreen contradiction\n\nAn element reported offscreen is not promoted.\n\n## Deliberate non-goals\n\nv0.16 does not yet:\n\n- prove selector uniqueness among siblings;\n- walk UIA ancestry;\n- compose parent/child selectors;\n- use RuntimeId as stable identity;\n- invoke controls;\n- set values;\n- capture typed text;\n- inject desktop input;\n- execute desktop.interaction operations.\n\n## Next rung\n\nv0.17 should add selector-scoping and replay revalidation.\n\nThe provider should be able to reconstruct a candidate UIA element inside the\nexpected process/window, prove that a recorded selector resolves uniquely, and\nreturn CLEAR / HOLD evidence before any future desktop interaction adapter is\nallowed to act.\n
