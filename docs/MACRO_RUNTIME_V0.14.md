# Macro Runtime v0.14 — Observation-Only Ghost-Walk Capture Adapter\n\n## Status\n\nv0.14 connects host-observed pointer clicks to the merged v0.13 Ghost-Walk\nrecorder without adding desktop input injection.\n\nThe adapter observes.\n\nIt does not click.\n\n## Core boundary\n\n~~~\nCAPTURE != EXECUTION\nOBSERVED INPUT != AUTHORITY\nINJECTED INPUT != HUMAN DEMONSTRATION\nWINDOW LOOKUP != TARGET AUTHORIZATION\nSEMANTIC LOOKUP FAILURE != LOST HUMAN ACTION\nCAPTURE RECEIPT != EXECUTION RECEIPT\n~~~\n\n## PointerClickEvent\n\nA host listener may submit one PointerClickEvent containing:\n\n- explicit event ID;\n- desktop x/y pixels;\n- LEFT / RIGHT / MIDDLE button;\n- timezone-aware observation timestamp;\n- injected-event flag;\n- zero authority flags.\n\nv0.14 records LEFT clicks only.\n\nRIGHT and MIDDLE clicks are HELD rather than silently converted into a left-click\ndraft.\n\nInjected events are also HELD before window lookup.\n\nThis prevents a future replay adapter from teaching the recorder from its own\ngenerated clicks.\n\n## Session re-anchor\n\nBefore every capture attempt, the adapter reconstructs and validates the persisted\nv0.13 Ghost-Walk session and observation chain.\n\nThe adapter therefore does not trust an in-memory session cursor.\n\nIf the session is missing or its observation chain is corrupt, capture fails\nclosed before processing the new event.\n\n## WindowFrameProvider\n\nWindow context is supplied through a read-only provider contract:\n\n~~~\nframe_for_click(event) -> WindowFrame | None\n~~~\n\nThe provider cannot grant execution authority.\n\nThe captured frame must contain the observed desktop coordinate or the event is\nHELD as CLICK_OUTSIDE_WINDOW.\n\n## Windows provider\n\nv0.14 includes WindowsWindowFrameProvider.\n\nIt uses user32 read APIs to:\n\n- resolve the window under the observed pointer coordinate;\n- normalize to the root window;\n- capture window rectangle;\n- capture process ID;\n- hash the current window title;\n- capture per-window DPI when available;\n- record whether the window is currently foreground.\n\nIt performs no SendInput, mouse_event, PostMessage, or other input injection.\n\nThe provider is observation-only.\n\n## SemanticTargetProvider\n\nSemantic enrichment is optional.\n\nA provider may attempt:\n\n~~~\ntarget_for_click(event, frame) -> SemanticTarget | None\n~~~\n\nResults are classified as:\n\n~~~\nFOUND\nNOT_FOUND\nERROR\nNOT_CONFIGURED\n~~~\n\nIf semantic lookup returns a target, the v0.13 recorder prefers SEMANTIC.\n\nIf it returns no target, the recorder retains WINDOW_RELATIVE_PIXEL fallback.\n\nIf semantic lookup throws an error, v0.14 still records the demonstrated click\nusing the guarded pixel anchor and marks the capture receipt with\nSEMANTIC_LOOKUP_ERROR.\n\nA semantic subsystem failure therefore does not erase a human demonstration.\n\n## Capture outcomes\n\nCaptureStatus is:\n\n~~~\nRECORDED\nHELD\n~~~\n\nHELD reasons currently include:\n\n~~~\nINJECTED_EVENT\nUNSUPPORTED_BUTTON\nWINDOW_UNAVAILABLE\nCLICK_OUTSIDE_WINDOW\n~~~\n\nA semantic lookup error is recorded as a successful pixel-fallback observation\nwith explicit error provenance.\n\n## Capture receipt\n\nReality Ledger adds:\n\n~~~\nghostwalk-capture-receipts.jsonl\n~~~\n\nEach GhostWalkCaptureReceipt binds:\n\n- session ID;\n- event ID/hash;\n- window provider ID;\n- optional semantic provider ID;\n- semantic lookup status;\n- RECORDED / HELD status;\n- reason;\n- frame hash when available;\n- semantic target hash when found;\n- resulting v0.13 observation hash when recorded;\n- preferred targeting strategy when recorded;\n- zero authority flags.\n\nMechanical invariants prevent contradictory receipts. For example:\n\n- FOUND requires a semantic provider and target hash;\n- non-FOUND cannot claim a semantic target hash;\n- NOT_CONFIGURED cannot name a semantic provider;\n- HELD cannot claim a resulting observation;\n- RECORDED must bind frame, observation, and preferred strategy.\n\n## v0.14 acceptance gates\n\n### CAPTURE-001 — semantic human click\n\nA real non-injected LEFT click with a semantic target records one v0.13\nobservation with SEMANTIC preferred.\n\n### CAPTURE-002 — pixel fallback\n\nA valid human click with no semantic target records WINDOW_RELATIVE_PIXEL.\n\n### CAPTURE-003 — injected input exclusion\n\nAn injected event is HELD before window lookup and creates no demonstration\nobservation.\n\n### CAPTURE-004 — unsupported button\n\nRIGHT/MIDDLE input is HELD rather than miscompiled.\n\n### CAPTURE-005 — missing window\n\nAn event with no resolvable window is HELD.\n\n### CAPTURE-006 — frame mismatch\n\nA provider frame that does not contain the observed click is HELD.\n\n### CAPTURE-007 — semantic subsystem failure\n\nA semantic-provider exception is recorded as an ERROR while preserving the\nhuman click through the window-relative pixel fallback.\n\n### CAPTURE-008 — immutable evidence\n\nCapture receipts are persisted separately from execution receipts and remain\nzero-authority.\n\n### CAPTURE-009 — platform boundary\n\nWindowsWindowFrameProvider refuses construction on non-Windows systems.\n\n### CAPTURE-010 — zero-authority event\n\nPointerClickEvent carries no operational, action, or execution authority.\n\n## What is now complete\n\nPhiOS now has a full observation path from a host click event to a proposed\nmacro:\n\n~~~\nhost-observed click\n→ PointerClickEvent\n→ validate persisted Ghost-Walk session\n→ resolve current window\n→ optional semantic lookup\n→ v0.13 GhostWalkRecorder\n→ hash-chained observation\n→ zero-authority MacroDefinition draft\n~~~\n\nNo part of that path injects desktop input.\n\n## Deliberate non-goals\n\nv0.14 does not yet:\n\n- install a global Windows mouse hook;\n- run a Windows message loop;\n- continuously listen in the background;\n- capture keyboard input;\n- capture typed text or secrets;\n- perform UI Automation semantic discovery itself;\n- inject mouse or keyboard input;\n- execute desktop.interaction operations.\n\n## Next rung\n\nv0.15 should add a Windows Ghost-Walk Listener around this adapter.\n\nThe listener should install a low-level observation hook, translate genuine\nhuman LEFT-button events into PointerClickEvent objects, preserve the OS\ninjected-event flag, and feed v0.14.\n\nIt must remain observation-only and must never share an input-injection path.\n
