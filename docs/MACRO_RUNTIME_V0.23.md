# Macro Runtime v0.23 — Ghost-Walk Baseline Refresh Service\n\n## Status\n\nv0.23 adds a host-driven refresh service around the merged v0.22 transition\ncoordinator so Ghost-Walk can keep one fresh pre-action semantic baseline armed\nacross long-running demonstrations without moving UIA work into WH_MOUSE_LL.\n\nThe service is explicit, bounded, receipt-driven, and zero-authority.\n\n## Core boundary\n\n~~~\nREFRESH SERVICE != AUTHORITY\nFRESH BASELINE != PERMISSION\nAGING BASELINE != STALE BASELINE\nFAILED REFRESH != REUSE OLD BASELINE\nSCOPE DRIFT != SAME BASELINE\nCLICK COORDINATION != BACKGROUND REFRESH\nHEALTH METRIC != EXECUTION PROOF\n~~~\n\n## Host-driven service model\n\nv0.23 deliberately does not create a hidden autonomous thread.\n\nThe host calls:\n\n~~~\narm(session_id)\ntick()\nhandle_listener_outcome(outcome)\ndisarm()\n~~~\n\nThis keeps scheduling visible and testable while allowing a shell/service host\nto call tick at a regular bounded cadence.\n\nAll refresh and click-coordination paths are serialized under one re-entrant\nlock.\n\nThat prevents the service from replacing the coordinator baseline while a click\nis simultaneously consuming it.\n\n## Refresh interval\n\nDefaults:\n\n~~~\nDEFAULT_REFRESH_INTERVAL_MS = 500\nMIN_REFRESH_INTERVAL_MS = 50\nMAX_REFRESH_INTERVAL_MS = 2500\n~~~\n\nThe configured refresh interval must be strictly less than the v0.22\ncoordinator max-baseline-age boundary.\n\nThis guarantees the service's planned refresh point occurs before the baseline\nwould become stale under normal ticking.\n\n## Arm\n\narm(session_id) clears any prior baseline and immediately asks v0.22 to capture\na fresh BEFORE baseline.\n\nSuccessful arm:\n\n~~~\nstatus = FRESH\nreason = ARMED\nrefreshed = true\n~~~\n\nFailed initial capture:\n\n~~~\nstatus = DEGRADED\nreason = BASELINE_CAPTURE_FAILED\nbaseline = null\n~~~\n\nThe service remains armed and future ticks may recover by capturing a fresh\nbaseline.\n\n## Tick behavior\n\nEvery tick observes the current frame outside the low-level mouse hook.\n\n### Matching young baseline\n\nIf the baseline is younger than refresh_interval_ms and still matches the exact\nstable frame scope:\n\n~~~\nFRESH / BASELINE_RETAINED\n~~~\n\nNo UIA refresh is performed.\n\n### Aging baseline\n\nIf age is at or beyond refresh_interval_ms:\n\n~~~\ncapture new v0.22 baseline\n-> FRESH / BASELINE_REFRESHED\n~~~\n\nThe old baseline is not retained as fallback if the refresh fails.\n\n### Scope drift\n\nIf process/window title/geometry/DPI/foreground state differs:\n\n~~~\ninvalidate current baseline\n-> attempt immediate refresh in new scope\n-> FRESH / SCOPE_DRIFT_REFRESHED\n~~~\n\nIf the replacement cannot be captured, the service remains DEGRADED with no\nbaseline.\n\n### Frame unavailable\n\nIf current foreground frame observation is missing or not foreground:\n\n~~~\nclear baseline\n-> DEGRADED / FRAME_UNAVAILABLE\n~~~\n\n## Automatic post-click re-arm\n\nhandle_listener_outcome() holds the same service lock while delegating to the\nv0.22 coordinator.\n\nv0.22 consumes the current baseline exactly once.\n\nAfter coordination completes or holds, v0.23 immediately attempts to capture a\nnew baseline for the still-armed session.\n\nSuccess:\n\n~~~\nFRESH / POST_ACTION_REARMED\n~~~\n\nFailure:\n\n~~~\nDEGRADED / POST_ACTION_REARM_FAILED\n~~~\n\nThis prevents a completed demonstration cycle from leaving Ghost-Walk silently\nunarmed for the next human click.\n\n## Disarm\n\ndisarm() clears the coordinator baseline, removes the active session, and emits:\n\n~~~\nDISARMED / DISARMED\n~~~\n\nLater ticks remain idle until a new arm().\n\n## Health surface\n\nBaselineHealthSnapshot exposes:\n\n- armed/disarmed;\n- active session ID;\n- current baseline SHA-256;\n- baseline age in milliseconds;\n- configured refresh interval;\n- v0.22 maximum baseline age;\n- refresh_due;\n- observation timestamp.\n\nHealth is informational only and carries no authority.\n\n## Receipt chain\n\nReality Ledger adds:\n\n~~~\nbaseline-refresh-receipts.jsonl\n~~~\n\nEvery BaselineRefreshReceipt binds:\n\n- service ID;\n- contiguous per-service sequence;\n- ARM / TICK / COORDINATION / DISARM;\n- session ID;\n- FRESH / DEGRADED / DISARMED;\n- exact reason;\n- timestamp;\n- current frame hash when observed;\n- current and prior baseline hashes;\n- baseline age;\n- refreshed / invalidated flags;\n- optional v0.22 coordinator receipt hash;\n- previous refresh-receipt hash;\n- zero authority flags.\n\nThe ledger refuses to allocate the next sequence if persisted sequence numbers\nor previous-receipt links are broken.\n\n## Anti-drift properties\n\nv0.23 freezes several long-cycle rules:\n\n~~~\nfailed refresh -> no stale fallback\nscope drift -> old baseline invalidated\nclick consumes baseline -> automatic re-arm\ndisarm -> no hidden refresh\nrefresh and click handling -> serialized\nreceipt history -> contiguous hash chain\n~~~\n\nThese directly target the repeat degradation and random desktop-state drift\nreported by real macro-recorder users.\n\n## Acceptance gates\n\n### REFRESH-001 — arm captures baseline\n\nArming immediately establishes a FRESH baseline and health snapshot.\n\n### REFRESH-002 — young baseline retained\n\nA matching baseline younger than the refresh interval is retained without UIA\nrecapture.\n\n### REFRESH-003 — aging baseline refresh\n\nAn aging baseline is replaced before the v0.22 stale boundary.\n\n### REFRESH-004 — scope drift replacement\n\nWindow-scope drift invalidates the old baseline and captures a replacement.\n\n### REFRESH-005 — frame unavailable\n\nMissing foreground state clears the current baseline and degrades health.\n\n### REFRESH-006 — failed refresh\n\nA failed replacement never falls back to the stale prior baseline.\n\n### REFRESH-007 — automatic post-action re-arm\n\nAfter v0.22 consumes a baseline, the service immediately captures a fresh one.\n\n### REFRESH-008 — disarm\n\nDisarm clears baseline/session and later ticks perform no refresh.\n\n### REFRESH-009 — receipt continuity\n\nRepeated cycles produce contiguous per-service sequences and exact previous-hash\nlinks with no authority flags.\n\n### REFRESH-010 — cadence safety\n\nA refresh interval at or beyond the v0.22 stale boundary is rejected.\n\n## Deliberate non-goals\n\nv0.23 does not yet:\n\n- own an OS thread or timer;\n- persist/reconstruct armed service state after process restart;\n- adapt cadence based on observed UI volatility;\n- infer keyboard demonstrations;\n- automatically accept inferred postconditions;\n- create execution authority.\n\n## Next rung\n\nv0.24 should add a real Ghost-Walk host service loop around the listener,\nbaseline refresh service, and transition coordinator.\n\nThat host should own lifecycle/start-stop semantics, bounded tick scheduling,\nlistener delivery, clean shutdown, service health reporting, and restart-safe\nrecovery without moving expensive UIA work into the hook callback.
