# Macro Runtime v0.13 — Ghost-Walk Demonstration Recorder\n\n## Status\n\nImmutable human-demonstration capture plus deterministic zero-authority draft\nMacroDefinition compilation.\n\nv0.13 turns the v0.12 interaction-anchor idea into a real demonstration\ncontract without adding a desktop input injector.\n\n## Core boundary\n\n~~~\nDEMONSTRATION != AUTHORITY\nOBSERVED CLICK != EXECUTABLE PERMISSION\nDRAFT MACRO != APPROVED MACRO\nSEMANTIC TARGET != TRUSTED CURRENT TARGET\nPIXEL FALLBACK != BLIND DESKTOP REPLAY\nABSOLUTE DESKTOP PIXEL != PREFERRED TARGET\n~~~\n\n## Session\n\nA GhostWalkSession binds:\n\n- explicit session ID;\n- recorder/operator identity;\n- timezone-aware start timestamp;\n- zero authority flags;\n- deterministic session SHA-256.\n\nSessions are persisted in:\n\n~~~\nghostwalk-sessions.jsonl\n~~~\n\nSession IDs are unique and cannot be silently reused.\n\n## Click observation\n\nv0.13 records CLICK demonstrations only.\n\nEach GhostWalkObservation binds:\n\n- session identity and session hash;\n- contiguous sequence index;\n- action kind;\n- observation timestamp;\n- exact WindowFrame hash;\n- v0.12 PixelAnchor;\n- optional SemanticTarget;\n- previous observation SHA-256;\n- zero authority flags.\n\nObservations are persisted in:\n\n~~~\nghostwalk-observations.jsonl\n~~~\n\nThe chain must remain contiguous and hash-linked.\n\nModified persisted observations fail closed.\n\n## Semantic target\n\nA SemanticTarget may record a stable UI identity discovered during the\ndemonstration, such as:\n\n~~~\nprovider = uia\nselector = automation_id=save-button\nrole = button\nname_hint = Save\n~~~\n\nThe semantic target is preferred during draft compilation because it describes\nwhat control the human intended rather than only where the pointer happened to\nbe.\n\n## Pixel fallback\n\nEvery click also retains the v0.12 window-relative PixelAnchor.\n\nThe anchor keeps:\n\n- source window/frame hash;\n- process identity;\n- window title hash;\n- normalized x/y location inside the window;\n- original absolute desktop x/y as observation evidence.\n\nIf no semantic target exists, the compiler chooses:\n\n~~~\nWINDOW_RELATIVE_PIXEL\n~~~\n\nnot fixed desktop-coordinate replay.\n\nAbsolute x/y values are retained for provenance and debugging only.\n\nThis remains valid when a secondary display has negative desktop coordinates.\n\n## Target priority\n\nThe draft compiler uses:\n\n~~~\nsemantic target when present\n    ↓ otherwise\nguarded window-relative PixelAnchor\n~~~\n\nBoth representations may be carried in the proposed operation so a future\ndesktop adapter can revalidate semantics and retain the pixel anchor as guarded\nfallback evidence.\n\n## Draft MacroDefinition\n\ncompile_draft() converts each observed click into one zero-authority DO step.\n\nThe proposed operation uses:\n\n~~~\nadapter_id = desktop.interaction\naction = click\nrequired_capabilities = (ui.interact,)\nexecution_modes_supported = LIVE only\nidempotency = UNKNOWN\nreplay = NON_REPLAYABLE\nrollback = NONE\nside_effect = UNKNOWN\n~~~\n\nThe adapter intentionally does not exist yet.\n\nThat means v0.13 defines the operation contract without accidentally making the\ndemonstration executable.\n\nEach operation also carries:\n\n- source observation SHA-256;\n- preferred target strategy;\n- process identity;\n- window-title hash;\n- PixelAnchor contract;\n- optional SemanticTarget contract;\n- guard_required = true;\n- absolute_pixel_is_evidence_only = true.\n\n## Draft compilation receipt\n\nReality Ledger adds:\n\n~~~\nghostwalk-draft-receipts.jsonl\n~~~\n\nA GhostWalkDraftReceipt binds:\n\n- session ID/hash;\n- observation count;\n- observation-chain head hash;\n- proposed macro ID/version;\n- MacroDefinition SHA-256;\n- exact operation hashes;\n- semantic-preferred count;\n- pixel-fallback count;\n- zero authority flags.\n\nCompiling the exact same demonstration into the same macro identity is\ndeterministic.\n\n## Jeffrey-derived ghost-walk model\n\nThe practical workflow is now:\n\n~~~\nhuman performs click\n→ capture exact window frame\n→ retain original desktop pixel as evidence\n→ normalize click inside the window\n→ attach semantic selector when available\n→ hash-chain the demonstration observation\n→ compile zero-authority draft operation\n~~~\n\nThis is meaningfully different from a traditional recorder that merely stores:\n\n~~~\nmove mouse to 500,350\nclick\n~~~\n\nv0.13 records both what the user appeared to target and where the demonstration\noccurred inside a verified application/window frame.\n\n## v0.13 acceptance gates\n\n### GHOST-001 — semantic preference\n\nA click with a SemanticTarget compiles with SEMANTIC as the preferred strategy,\nwhile retaining its guarded PixelAnchor.\n\n### GHOST-002 — pixel fallback\n\nA click without semantic identity compiles with WINDOW_RELATIVE_PIXEL.\n\n### GHOST-003 — deterministic chained demonstration\n\nObservations are contiguous and hash-linked. Recompiling the same chain yields\nthe same MacroDefinition and draft-receipt hashes.\n\n### GHOST-004 — tamper detection\n\nModified observation or nested PixelAnchor evidence fails reconstruction.\n\n### GHOST-005 — unique session identity\n\nA demonstration session ID cannot be reused.\n\n### GHOST-006 — non-empty draft\n\nAn empty demonstration cannot compile into a macro.\n\n### GHOST-007 — multi-monitor evidence\n\nNegative absolute desktop coordinates remain valid observation evidence.\n\n### GHOST-008 — zero authority\n\nSession, observation, draft definition, and compilation receipt remain\nzero-authority artifacts.\n\n## Deliberate non-goals\n\nv0.13 does not yet:\n\n- hook real OS mouse events;\n- inject mouse clicks;\n- capture keyboard/text entry;\n- capture drag/drop;\n- capture scrolling;\n- discover accessibility selectors itself;\n- execute desktop.interaction operations;\n- convert timing gaps into WAIT steps;\n- infer loops from repeated demonstrations;\n- infer conditions from UI state;\n- capture passwords or secret text.\n\n## Next rung\n\nv0.14 should add the first real Ghost-Walk Capture Adapter.\n\nIt should observe actual desktop input and window context, then feed the exact\nv0.13 recorder contract.\n\nThe capture adapter should remain observation-only.\n\nA separate later Desktop Interaction Adapter may execute compiled operations only\nafter the v0.12 guard returns CLEAR and the normal macro authority path grants\nui.interact.\n
