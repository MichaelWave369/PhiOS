The earlier v0.60 pilot verified ThinkTank's real production React build and browser
render. This rung adds a **real upstream-committed npm lock** and a separate
**network-disabled container build** using a pre-staged package cache.

Neither this workflow nor a green receipt installs an application inside PhiOS.

### Actual workflow

The read-only PhiOS GitHub workflow:

1. Checks out the fixed ThinkTank commit. Rejects mismatched candidate provenance
   and any missing/untracked/modified `package-lock.json` or manifest.
2. Validates npm v3 lockfile structure, package version/integrity metadata and
   that the locked root dependencies match the source `package.json`.
3. Installs **using `npm ci` only** to warm a temporary cache, and executes
   upstream unit tests and real React build on the hosted runner.
4. Runs `npm audit --audit-level=high`; does not suppress advisories.
5. Pulls a Node 24 build image **before** isolation, then copies an exact Git
   archive into a disposable Docker container with `--network none`,
   `--read-only`, dropped Linux capabilities, and no-new-privileges.
6. Reinstalls using **`npm ci --offline`**, runs upstream tests and the actual
   production `npm run build` with **no container network access**.
   The only writable mounts are disposable build space and pre-staged npm cache.
7. Validates the offline-built static asset set, serves those bytes over local
   127.0.0.1 HTTP on the hosted runner, then checks actual ThinkTank React room
   mount in headless Chrome.
8. Uploads a bounded JSON receipt only. The compiled app, cached npm tarballs,
   local provider state, and browser profile are **not** shipped as app payloads.

The CI Docker image tag is not an independently attested image digest.
The host Chrome process is **not** a kernel-network-sandboxed browser; its
background networking is disabled but it uses the host networking stack.
