# Macro Runtime v0.21 — Windows Before/After Semantic-State Observer\n\n## Status\n\nv0.21 adds the real privacy-bounded Windows UI Automation sensor that produces\nthe exact GhostWalkUiStateSnapshot inputs consumed by the merged v0.20\ntransition inference engine.\n\nIt is observation-only.\n\nIt never performs desktop input and never reads control values.\n\n## Core boundary\n\n~~~\nUIA INVENTORY != AUTHORITY\nPARTIAL INVENTORY != VALID SNAPSHOT\nNAME HINT != STABLE IDENTITY\nDUPLICATE SELECTOR != UNIQUE TARGET\nOFFSCREEN CONTROL != CURRENT WINDOW STATE\nPROCESS MATCH != WINDOW SCOPE\nSTATE OBSERVATION != HUMAN INTENT\n~~~\n\n## Real Windows backend\n\nComtypesWindowsUiaInventoryBackend extends the existing optional v0.16\ncomtypes UI Automation backend.\n\nIt queries the Windows desktop UIA tree with an exact process-ID condition and\nbuilds privacy-bounded UiaElementSnapshots using the already-reviewed v0.16\nsnapshot conversion path.\n\nThe backend uses:\n\n~~~\nUIAutomationCore.dll\n-> CUIAutomation\n-> UIA_ProcessIdPropertyId\n-> FindAll(TreeScope_Descendants, process_condition)\n~~~\n\n## Hard inventory bounds\n\nv0.21 freezes:\n\n~~~\nMAX_UIA_INVENTORY_ELEMENTS = 512\nMAX_UIA_STATE_TARGETS = 128\n~~~\n\nIf the complete process-scoped UIA collection exceeds the scan bound:\n\n~~~\nHELD: INVENTORY_LIMIT_EXCEEDED\n~~~\n\nNo truncated snapshot is emitted.\n\nIf stable unique semantic targets exceed the target bound:\n\n~~~\nHELD: TARGET_LIMIT_EXCEEDED\n~~~\n\nNo truncated snapshot is emitted.\n\nThis prevents incomplete inventories from creating false appeared/disappeared\ntransitions later.\n\n## Window scoping\n\nThe process condition is not treated as sufficient window scope.\n\nAfter backend collection, the observer keeps only elements that:\n\n- belong to the exact expected process;\n- are not reported offscreen;\n- have a complete bounding rectangle;\n- fit fully inside the current expected WindowFrame.\n\nOnly those scoped snapshots are persisted through the existing\nuia-element-snapshots.jsonl evidence stream.\n\nElements from another window in the same process are not promoted merely because\nthey share a process ID.\n\n## Stable semantic identity\n\nAn inventory element becomes a semantic candidate only when AutomationId is\nnon-empty.\n\nThe selector is the same canonical v0.16 shape:\n\n~~~\n{\n  "automation_id": "...",\n  "control_type": 50000 | null\n}\n~~~\n\nStable identity for inventory comparison is based on:\n\n~~~\nprovider\nselector\nrole\n~~~\n\nand explicitly excludes:\n\n~~~\nname_hint\n~~~\n\nbecause a label may change while the underlying control remains the same.\n\nv0.20 transition comparison is updated with the same stable identity rule.\n\nTherefore a control changing from:\n\n~~~\nname_hint = "Save"\n~~~\n\nto:\n\n~~~\nname_hint = "Saved"\n~~~\n\nwith the same selector does not fabricate a disappeared + appeared transition.\n\n## Duplicate selector identities\n\nIf two UIA elements expose the same stable semantic identity, both are treated\nas ambiguous for inventory purposes.\n\nThey are excluded from the unique semantic target set rather than deduplicated\ninto a fake unique control.\n\nThe receipt records:\n\n~~~\nambiguous_identity_count\n~~~\n\nso the loss of usable identity is visible.\n\n## Privacy boundary\n\nv0.21 reuses the v0.16 identity-only snapshot surface.\n\nIt does not read:\n\n- ValuePattern values;\n- typed field contents;\n- password contents;\n- document text;\n- clipboard contents;\n- help text.\n\nPassword controls may retain AutomationId/control-type identity, but their\nSemanticTarget name hint is always removed.\n\nThe receipt records how many password name hints were excluded.\n\n## Observer receipt\n\nReality Ledger adds:\n\n~~~\nuia-state-observer-receipts.jsonl\n~~~\n\nEach UiaStateObservationReceipt binds:\n\n- session ID;\n- demonstrated action observation SHA-256;\n- BEFORE / AFTER phase;\n- WindowFrame SHA-256;\n- observation timestamp;\n- backend ID;\n- CAPTURED / HELD;\n- exact reason;\n- scanned element count;\n- window-scoped element count;\n- semantic candidate count;\n- unique target count;\n- ambiguous identity count;\n- excluded password-name count;\n- complete_inventory flag;\n- sorted target hashes;\n- complete nested GhostWalkUiStateSnapshot when captured;\n- zero authority flags.\n\nThe nested snapshot makes the state observation durable even before a later\nv0.20 inference call persists its own inference-bound state evidence.\n\n## Failure behavior\n\n### Non-foreground frame\n\n~~~\nHELD: FRAME_NOT_FOREGROUND\n~~~\n\nThe backend is not queried.\n\n### Inventory too large\n\n~~~\nHELD: INVENTORY_LIMIT_EXCEEDED\n~~~\n\n### Too many stable targets\n\n~~~\nHELD: TARGET_LIMIT_EXCEEDED\n~~~\n\n### UIA/backend failure\n\n~~~\nHELD: BACKEND_ERROR\n~~~\n\nAll HELD receipts set:\n\n~~~\ncomplete_inventory = false\nsnapshot = null\ntarget_sha256s = []\n~~~\n\nA partial observation is never fed into v0.20 as if it were complete.\n\n## Full v0.21 data path\n\n~~~\nfresh WindowFrame\n-> process-scoped Windows UIA inventory\n-> complete bounded identity snapshots\n-> exact window-geometry scope\n-> strong AutomationId candidates\n-> duplicate selector suppression\n-> password-name redaction\n-> GhostWalkUiStateSnapshot\n-> v0.20 TransitionInference\n-> editable candidate postconditions\n~~~\n\n## Acceptance gates\n\n### STATE-001 — complete inventory\n\nA complete bounded scan produces a CAPTURED snapshot with deterministic stable\nsemantic targets.\n\n### STATE-002 — duplicate selector identity\n\nTwo elements with the same selector identity remain ambiguous even when their\nname hints differ.\n\n### STATE-003 — password redaction\n\nPassword-control semantic targets omit the descriptive name hint.\n\n### STATE-004 — window scope\n\nWrong-process, offscreen, and out-of-window controls are excluded and are not\npersisted as scoped state evidence.\n\n### STATE-005 — foreground requirement\n\nA non-foreground frame HOLDs before backend observation.\n\n### STATE-006 — inventory overflow\n\nAn oversized backend scan HOLDs without producing a partial snapshot.\n\n### STATE-007 — backend error\n\nA backend failure HOLDs without producing a partial snapshot.\n\n### STATE-008 — target overflow\n\nMore than 128 unique stable semantic targets HOLDs instead of truncating.\n\n### STATE-009 — descriptive label drift\n\nA name-hint-only change does not create v0.20 transition noise.\n\n### STATE-010 — inference integration\n\nReal observer outputs feed v0.20 and produce deterministic transition candidates.\n\n### STATE-011 — impossible scan count\n\nInventory contracts above the frozen hard bound are rejected.\n\n### STATE-012 — platform boundary\n\nThe real comtypes inventory backend refuses construction on non-Windows systems.\n\n## Hook timing boundary\n\nv0.21 deliberately does not perform a full UIA inventory inside WH_MOUSE_LL.\n\nThe merged v0.15 low-level hook callback remains minimal:\n\n~~~\ncopy event\n-> bounded queue\n-> CallNextHookEx\n~~~\n\nTree enumeration inside the hook callback would risk Windows hook timeout and\nlong-cycle observation failure.\n\nv0.21 is the real state sensor, not yet the timing/orchestration layer that\nautomatically pairs a pre-click baseline with a post-click snapshot.\n\n## Deliberate non-goals\n\nv0.21 does not yet:\n\n- block inside the mouse hook to collect UIA state;\n- continuously sample UIA state in the background;\n- automatically bind the most recent baseline to a click;\n- infer or adopt human intent;\n- attach inferred postconditions to an executable macro;\n- read field values or secrets;\n- create execution authority.\n\n## Next rung\n\nv0.22 should add the Ghost-Walk demonstration transition coordinator.\n\nIt should maintain a safe pre-action semantic baseline outside the low-level hook,\nbind that baseline to the next genuine human click, capture a bounded post-action\nstate after the click, reject stale baselines, and feed the resulting pair into\nv0.20.\n\nThat is the rung that turns the v0.21 sensor into an automatic real-time\nbefore/action/after learning loop without sacrificing the v0.15 anti-timeout\nlistener design.
