# Macro Runtime v0.25 — Ghost-Walk Operator Control Surface\n\n## Status\n\nv0.25 adds the zero-authority operator-facing contract that PhiShell and Vessie\ncan use to observe and control the merged v0.24 Ghost-Walk host without\naccessing listener, UIA, baseline-service, coordinator, or execution internals.\n\n## Core boundary\n\n~~~\nUI CONTROL != EXECUTION AUTHORITY\nHOST CONTROL != ACTIONLEASE\nSTATUS VIEW != REALITY PROOF\nARM != PERMISSION TO ACT\nDISARM != STOP HOST\nLEARNED CANDIDATE != ACCEPTED INTENT\nRECOVERY HISTORY != LIVE BASELINE\n~~~\n\n## Control actions\n\nGhostWalkControlAction freezes five operator actions:\n\n~~~\nSTATUS\nSTART\nSTOP\nARM\nDISARM\n~~~\n\nSTART and STOP control the v0.24 host lifecycle.\n\nARM and DISARM control only the learning baseline through new host-mediated\narm_baseline() / disarm_baseline() methods.\n\nNeither command exposes v0.23 directly.\n\nDISARM pauses transition learning while leaving the listener/host alive.\n\n## Available-actions contract\n\nThe control snapshot computes the actions that are valid in the current state.\n\nTypical examples:\n\n~~~\nSTOPPED:\n  START\n  STATUS\n\nRUNNING + baseline armed:\n  DISARM\n  STOP\n  STATUS\n\nDEGRADED + baseline absent:\n  ARM\n  STOP\n  STATUS\n\nFAILED:\n  STOP\n  STATUS\n~~~\n\nAn unavailable action is rejected before calling the host.\n\nSTOP against an already stopped host is treated as an explicit NOOP rather than\nan error.\n\n## Control snapshot\n\nGhostWalkControlSnapshot exposes one compact UI-ready read model:\n\n- surface ID;\n- host ID/status;\n- run generation;\n- session ID;\n- listener/tick liveness;\n- baseline armed/hash/age/refresh-due;\n- current host error type;\n- recovery state and recovery receipt;\n- currently available actions;\n- last Ghost-Walk action-observation hash;\n- recent learned transition summaries;\n- recent host/coordinator/baseline issues;\n- observation timestamp;\n- zero authority flags.\n\nThe snapshot has a canonical SHA-256.\n\n## Learned transitions\n\nRecent v0.20 TransitionInference receipts are projected into\nLearnedTransitionSummary values.\n\nEach summary exposes:\n\n- inference receipt hash;\n- session ID;\n- exact demonstrated action-observation hash;\n- inference status;\n- sorted candidate expectation kinds;\n- inference timestamp;\n- latest editable OperatorLog revision hash/number/status when present.\n\nThis lets PhiShell show what Ghost Walk thinks changed while preserving the\nseparation between immutable inference evidence and editable human notes.\n\n## Recent issues\n\nThe control surface aggregates recent trouble from three layers:\n\n~~~\nHOST\nTRANSITION_COORDINATOR\nBASELINE_REFRESH\n~~~\n\nOnly meaningful degraded/held/failure evidence is included.\n\nIssues are normalized into:\n\n- source;\n- status;\n- exact reason;\n- observation timestamp;\n- source receipt SHA-256.\n\nResults are sorted newest first and bounded.\n\n## Recovery visibility\n\nIf v0.24 recorded:\n\n~~~\nRECOVERY / PRIOR_RUN_ABANDONED\n~~~\n\nthe control snapshot exposes:\n\n~~~\nrecovery_state = PRIOR_RUN_ABANDONED\nrecovery_receipt_sha256 = ...\n~~~\n\nThe surface never interprets that as a recovered baseline.\n\n## Control receipts\n\nReality Ledger adds:\n\n~~~\nghostwalk-control-receipts.jsonl\n~~~\n\nEvery operator request records:\n\n- surface ID;\n- contiguous per-surface sequence;\n- STATUS / START / STOP / ARM / DISARM;\n- requested session ID when supplied;\n- OBSERVED / APPLIED / NOOP / REJECTED;\n- exact reason;\n- before control-snapshot SHA-256;\n- after control-snapshot SHA-256;\n- timestamp;\n- optional error type;\n- previous control-receipt SHA-256;\n- zero authority flags.\n\nThe ledger refuses to allocate the next sequence if the control receipt chain is\nbroken.\n\n## Host-mediated learning pause\n\nv0.25 adds two safe methods to GhostWalkHostService:\n\n~~~\narm_baseline()\ndisarm_baseline()\n~~~\n\nBoth require an active RUNNING or DEGRADED host.\n\ndisarm_baseline():\n\n- disarms v0.23;\n- leaves listener and tick workers alive;\n- marks host DEGRADED;\n- prevents valid transition learning until re-armed.\n\narm_baseline():\n\n- captures a new v0.23 baseline for the current session;\n- returns RUNNING when fresh;\n- remains DEGRADED if fresh baseline capture fails.\n\nThese are observation lifecycle controls only.\n\n## Acceptance gates\n\n### CONTROL-001 — stopped surface\n\nA stopped host exposes only START and STATUS and carries zero authority.\n\n### CONTROL-002 — start/stop\n\nSTART and STOP route through the host and produce append-only control receipts.\n\n### CONTROL-003 — arm/disarm\n\nLearning pause/resume is mediated through the host, never through v0.23 directly.\n\n### CONTROL-004 — stopped STOP\n\nSTOP while already stopped becomes a NOOP.\n\n### CONTROL-005 — unavailable action\n\nAn unavailable ARM is rejected without invoking the host.\n\n### CONTROL-006 — learned transition projection\n\nRecent inference evidence is summarized and linked to the newest editable\nOperatorLog revision.\n\n### CONTROL-007 — issue aggregation\n\nRecent host failure, coordinator HOLD, and baseline degradation become one\nbounded newest-first issue stream.\n\n### CONTROL-008 — recovery visibility\n\nPRIOR_RUN_ABANDONED is visible without implying baseline recovery.\n\n### CONTROL-009 — STATUS\n\nSTATUS is observation-only and invokes no host mutation.\n\n### CONTROL-010 — control history integrity\n\nControl receipts remain contiguous, previous-hash linked, and zero-authority.\n\n### HOST-012 — learning pause\n\nHost disarm pauses baseline learning without stopping the listener.\n\n### HOST-013 — learning resume\n\nHost arm captures a fresh baseline without restarting the listener.\n\n## Deliberate non-goals\n\nv0.25 does not yet:\n\n- render React/PhiShell components;\n- expose an HTTP or IPC transport;\n- auto-accept inferred postconditions;\n- expose ActionLeases or governed execution internals;\n- grant action/execution authority;\n- control replay/execution macros.\n\n## Next rung\n\nv0.26 should bind this stable control contract into the actual PhiShell UI and\nlocal host bridge.\n\nThe visual panel can then render status, baseline freshness, recent transitions,\nrecovery/failure history, and START/STOP/ARM/DISARM controls while talking only\nto v0.25 rather than directly to Ghost-Walk internals.
