# Macro Runtime v0.24 — Ghost-Walk Host Service\n\n## Status\n\nv0.24 packages the merged Ghost-Walk listener, v0.23 baseline refresh service,\nv0.22 transition coordinator, and their existing evidence streams into one\nlong-running host lifecycle.\n\nThe host owns start/stop semantics, bounded tick scheduling, listener outcome\ndelivery, clean shutdown, health reporting, and restart-safe lifecycle recovery.\n\n## Core boundary\n\n~~~\nHOST SERVICE != AUTHORITY\nRUNNING != SAFE BASELINE\nPERSISTED HISTORY != LIVE PROCESS\nRECOVERED RUN != RECOVERED BASELINE\nTHREAD ALIVE != HEALTHY SEMANTIC STATE\nLISTENER FAILURE != SILENT CONTINUATION\nTICK FAILURE != STALE BASELINE FALLBACK\nSTOPPED HISTORY != RUNNING PROCESS\n~~~\n\n## Runtime topology\n\nv0.24 keeps the expensive work out of WH_MOUSE_LL.\n\n~~~\nWindowsGhostWalkListener\n  -> hook callback\n  -> bounded raw-event queue\n  -> listener observation worker\n  -> host outcome handler\n  -> v0.23 serialized coordination\n\nGhostWalkHostService tick thread\n  -> bounded wait\n  -> v0.23 tick()\n  -> baseline health / refresh\n~~~\n\nThe listener and tick loop remain separate workers.\n\nv0.23's lock still serializes baseline refresh against click coordination.\n\n## Start\n\nstart(session_id) performs:\n\n1. validate persisted host receipt history;\n2. identify and receipt any abandoned prior run;\n3. allocate a new run generation;\n4. arm v0.23 with a fresh baseline;\n5. construct the listener;\n6. start listener and tick threads;\n7. emit START lifecycle evidence.\n\nIf the initial baseline is fresh:\n\n~~~\nRUNNING / STARTED_FRESH\n~~~\n\nIf the service is armed but baseline capture is degraded:\n\n~~~\nDEGRADED / STARTED_DEGRADED\n~~~\n\nThe listener may still run while baseline health is degraded. v0.22 will not\nproduce valid transition inference without a valid baseline.\n\n## Real Windows factory\n\nGhostWalkHostService.from_windows() constructs the real stack:\n\n~~~\nGhostWalkBaselineRefreshService.from_windows()\nWindowsWindowFrameProvider\nWindowsUiaSemanticProvider\nGhostWalkCaptureAdapter\nGhostWalkListenerBridge\nWindowsGhostWalkListener\n~~~\n\nThe host does not inject desktop input.\n\n## Tick cadence\n\nDefault host tick:\n\n~~~\n100 ms\n~~~\n\nBounds:\n\n~~~\n25 ms <= tick_interval_ms <= 1000 ms\n~~~\n\nThe host tick interval cannot exceed the v0.23 baseline refresh interval.\n\nThis ensures the host calls the baseline service frequently enough for its\nconfigured refresh policy to operate.\n\n## Listener delivery\n\nEach GhostWalkListenerOutcome is delivered into:\n\n~~~\nv0.23 handle_listener_outcome()\n~~~\n\nwhich serializes:\n\n- v0.22 baseline consumption;\n- before/action/after coordination;\n- transition inference;\n- automatic post-action baseline re-arm.\n\nThe host receipts the listener receipt SHA-256, transition-coordinator receipt\nSHA-256, and v0.23 service receipt SHA-256.\n\n## Failure propagation\n\n### Listener failure\n\nIf the blocking listener exits with an exception:\n\n~~~\nFAILED / LISTENER_FAILED\n~~~\n\nIf it returns without an explicit host stop request:\n\n~~~\nFAILED / LISTENER_STOPPED_UNEXPECTEDLY\n~~~\n\n### Tick failure\n\nIf v0.23 tick() raises:\n\n~~~\nFAILED / TICK_FAILED\n~~~\n\nThe host requests listener stop and does not continue running against an\nunmaintained baseline.\n\nFAILED hosts remain explicitly stoppable so workers can be joined and the\nbaseline service can be disarmed.\n\n## Clean shutdown\n\nstop() performs:\n\n1. record STOP_REQUESTED;\n2. set the host stop event;\n3. request listener stop;\n4. join listener and tick threads with a bounded timeout;\n5. disarm v0.23;\n6. record STOPPED_CLEAN or SHUTDOWN_INCOMPLETE.\n\nDefault shutdown timeout:\n\n~~~\n10 seconds\n~~~\n\nMaximum:\n\n~~~\n30 seconds\n~~~\n\n## Restart recovery\n\nv0.24 persists host lifecycle history, but it never serializes or restores a\nlive baseline into a new process.\n\nOn start, the host validates every prior receipt hash and previous-receipt link.\n\nIf the last persisted host state is:\n\n~~~\nSTARTING\nRUNNING\nDEGRADED\nSTOPPING\n~~~\n\nthe new process records:\n\n~~~\nRECOVERY / PRIOR_RUN_ABANDONED\n~~~\n\nThen it allocates a new run generation and calls v0.23 arm() for a completely\nfresh baseline.\n\nTherefore:\n\n~~~\nRECOVERED HISTORY != RECOVERED BASELINE\n~~~\n\nA process restart can recover what happened, not reuse what was once observed.\n\n## Host health\n\nGhostWalkHostHealth exposes:\n\n- host status;\n- run generation;\n- active session;\n- listener thread alive;\n- tick thread alive;\n- baseline armed;\n- baseline SHA-256;\n- baseline age;\n- baseline refresh due;\n- error type;\n- observation timestamp.\n\nHealth is local runtime state only and carries no authority.\n\n## Persistent lifecycle evidence\n\nReality Ledger adds:\n\n~~~\nghostwalk-host-receipts.jsonl\n~~~\n\nEach GhostWalkHostReceipt binds:\n\n- host ID;\n- contiguous per-host sequence;\n- run generation;\n- RECOVERY / START / TICK / LISTENER / STOP / FAILURE;\n- session ID;\n- host status and exact reason;\n- timestamp;\n- v0.23 service receipt hash when applicable;\n- v0.22 coordinator receipt hash when applicable;\n- listener receipt hash when applicable;\n- current baseline hash/age when applicable;\n- listener/tick liveness observations;\n- abandoned-run recovery flag;\n- error type;\n- previous lifecycle receipt hash;\n- zero authority flags.\n\n## Integrity\n\nBefore a new run starts, v0.24 reconstructs every prior lifecycle receipt and\nverifies:\n\n- canonical receipt SHA-256;\n- contiguous sequence numbers;\n- exact previous-receipt hash chain;\n- stable host identity.\n\nTampered lifecycle history fails closed.\n\n## Acceptance gates\n\n### HOST-001 — clean start/stop\n\nA fresh host arms a baseline, starts workers, stops them, disarms v0.23, and\nrecords a clean lifecycle.\n\n### HOST-002 — bounded tick scheduling\n\nThe tick worker delivers v0.23 ticks at the configured host cadence.\n\n### HOST-003 — listener delivery\n\nA listener outcome reaches v0.23 and the host receipt binds listener,\ncoordinator, and refresh-service evidence.\n\n### HOST-004 — degraded startup\n\nA failed initial baseline does not fake RUNNING health; the host starts\nDEGRADED while the listener remains available for recovery.\n\n### HOST-005 — restart recovery\n\nA prior unclean RUNNING receipt becomes PRIOR_RUN_ABANDONED and the new run\ngeneration captures a new baseline instead of restoring the old one.\n\n### HOST-006 — tampered history\n\nModified persisted lifecycle evidence fails canonical hash validation before\na new run can start.\n\n### HOST-007 — listener failure\n\nListener exceptions become FAILED evidence and the failed host remains\nstoppable for cleanup.\n\n### HOST-008 — tick failure\n\nTick failure becomes FAILED evidence and requests listener termination.\n\n### HOST-009 — duplicate start\n\nA second start while active is rejected.\n\n### HOST-010 — cadence contract\n\nA host tick interval slower than the baseline refresh cadence is rejected.\n\n### HOST-011 — lifecycle chain\n\nHost receipts remain contiguous, hash-linked, and zero-authority.\n\n## Deliberate non-goals\n\nv0.24 does not yet:\n\n- install itself as a Windows Service;\n- auto-start on OS login;\n- expose a PhiShell control panel;\n- persist a live baseline across restart;\n- infer keyboard demonstrations;\n- auto-accept transition candidates;\n- grant execution authority.\n\n## Next rung\n\nv0.25 should add the operator-facing Ghost-Walk service control surface and\nstatus contract: arm/disarm, start/stop, current session, baseline age, degraded\nreason, recent learned transitions, and explicit recovery state.\n\nThat surface can then be wired into PhiShell/Vessie without giving the UI direct\nauthority over the lower execution primitives.
